How I Created a "Cheating Tool" for League of Legends

Published on ---, 2025 by me :)

⚠️ Educational Purposes Only

This project was created purely for educational purposes to explore computer vision and real-time data processing. It was never used in actual gameplay and is not intended to provide unfair advantages.

Introduction

Rift Recon is a real-time computer vision tool I developed to analyze the minimap in League of Legends. It detects, tracks, and reports enemy champion movements, delivering positional information to an in-game overlay via a WebSocket interface. Despite the tactical-sounding name, this project stemmed purely from a personal curiosity about applying computer vision in gaming environments — not from a desire to gain any unfair advantage.

What began as a simple experiment in object detection evolved into a comprehensive system built entirely on classical computer vision techniques. Rift Recon leverages real-time image processing and efficient tracking methods to maintain accurate champion detection throughout a live match. This project challenged me to optimize for frame-perfect timing, minimize CPU overhead, and build a detection pipeline capable of adapting to the fast-paced and ever-changing nature of in-game visuals.

Background

League of Legends is a multiplayer online battle arena (MOBA) game where map awareness and champion positioning are crucial for success. The minimap provides essential information about enemy locations, but only when enemies are visible to your team. This limitation creates interesting technical challenges for computer vision applications.

The idea for Rift Recon came from my interest in real-time computer vision and the technical challenge of processing live game footage. I wanted to explore how accurately I could detect and track moving objects in a dynamic environment with consistent lighting, colors, and visual elements - making it an ideal testbed for computer vision algorithms.

1. System Architecture

The Rift Recon system consists of several interconnected components working together to provide real-time champion detection and tracking. The architecture was designed with modularity and performance in mind, allowing each component to be optimized independently.

To better understand the system, I'll break down the architecture into 2 different perspectives: the "macro" view and the "meso" view.

1.1 The Solution Architecture (The "Macro" View)

Initially, everything lived in one giant main.cpp file. It worked—until it didn’t. As the project grew, things got messy fast. So I restructured the system into a clean, modular design.

A Three-Project Solution

  • RiftRecon-Core: A static library (.lib) that contains the main logic—frame analysis, champion tracking, and WebSocket communication.
  • RiftRecon-App: A simple executable (.exe) that initializes and runs the core system.
  • RiftRecon-Tests: A separate testing suite using Google Test to validate the core library’s behavior and accuracy.

This separation keeps the system organized and makes it easier to test, debug, and extend. Each project has a clear role, and the logic-heavy Core can be reused or upgraded independently of the App or Tests.

1.2 The Core Library Architecture (The "Meso" View)

Inside the "Brain" (our RiftRecon-Core library), I didn't want chaos. I used Object-Oriented Programming to assign clear roles, like assembling a team of specialists. The main boss is the ApplicationController class. It acts as the conductor of an orchestra—it doesn't play an instrument itself, but it initializes and coordinates all the other major components to make sure they work in harmony.

The biggest engineering challenge here was performance. This tool absolutely cannot cause lag mid-game. The solution was the multi-threaded GameCaptureEngine, which I designed like a well-oiled, two-person assembly line:

  1. The Watcher (Capture Thread): One thread's only job is to furiously grab frames from the screen using DirectX and drop them into a shared queue. It runs uninterrupted, ensuring we never miss a moment.
  2. The Thinker (Processing Thread): A second thread pulls frames from that queue and handles all the heavy lifting. This is where the ChampionDetector gets to run its OpenCV magic.

By decoupling capturing and processing, the app stays perfectly smooth. When a detection is made, the result is handed off to the WebSocketServer, which then shouts the update to the in-game overlay.

Frame Capturing

The frame capturing system is responsible for efficiently extracting screen data from the League of Legends client in real-time. This component uses optimized screen capture APIs to minimize CPU overhead while maintaining the high frame rates necessary for accurate detection.

The system focuses specifically on the minimap region, using intelligent region detection to automatically locate and crop the relevant area regardless of game resolution or UI scaling. This targeted approach significantly reduces the amount of data that needs to be processed downstream.

Frame Processing

Frame processing encompasses the core computer vision algorithms that analyze captured minimap data. Using a combination of template matching and feature detection, the system identifies champion icons with high accuracy while accounting for visual variations like different skins and lighting effects.

The processing pipeline includes preprocessing steps for noise reduction and contrast enhancement, followed by multi-scale template matching to handle different icon sizes. Advanced filtering techniques eliminate false positives and ensure robust detection across varying game conditions.

In-game Overlay

The in-game overlay system renders detected champion positions directly onto the game screen, providing real-time visual feedback. This component receives position data through the WebSocket interface and displays it using transparent overlay graphics that don't interfere with normal gameplay.

The overlay includes features like movement prediction trails, last-seen indicators, and customizable visual elements. The rendering system is optimized for minimal performance impact while maintaining clear visibility of tracked information during intense gameplay moments.

Conclusion

Rift Recon represents a fascinating intersection of computer vision, real-time processing, and gaming technology. While created for educational purposes, the project provided invaluable experience in developing high-performance computer vision systems and working with real-time data streams.

The techniques and optimizations developed for this project have applications far beyond gaming, from surveillance systems to autonomous vehicles. Most importantly, it reinforced my passion for computer vision and real-time systems development.

The complete source code and documentation for this project demonstrate advanced computer vision techniques and serve as a learning resource for others interested in real-time image processing applications.

Technical Challenges

Developing Rift Recon presented numerous technical challenges, from handling varying game conditions to optimizing for real-time performance. Some of the most significant challenges included:

  • Frame Rate Consistency: Maintaining stable processing speeds across different system configurations
  • Visual Variations: Handling different champion skins, map themes, and visual effects
  • Memory Management: Preventing memory leaks in long-running real-time applications
  • False Positive Reduction: Distinguishing between actual champions and similar visual elements

Lessons Learned

This project taught me valuable lessons about real-time computer vision, performance optimization, and system architecture. Working with live data streams highlighted the importance of robust error handling and the challenges of maintaining consistency in dynamic environments.

Perhaps most importantly, the project demonstrated the ethical considerations involved in developing tools that could potentially affect competitive gaming environments, reinforcing the importance of responsible development practices.
